# Meridian Analytics — Embedding API v2 and v3 Comparison

**Document ID:** doc_api_embedding
**Owner:** Platform Engineering
**Last updated:** 2026-03-15

## Overview

The Meridian Embedding API converts documents and queries into dense vector representations for similarity search and retrieval. Two versions of the Embedding API are currently supported: version 2 (v2) and version 3 (v3). This document compares the key differences between Embedding API v2 and v3 in terms of supported dimensions and pricing per token, helping customers choose the appropriate version for their use case.

## Endpoints

- **v2:** `POST https://api.meridian-analytics.com/v2/embeddings`
- **v3:** `POST https://api.meridian-analytics.com/v3/embeddings`

## Key differences between Embedding API v2 and v3

The following table summarizes the key differences between Embedding API v2 and v3 in terms of supported dimensions and pricing per token:

| Feature | Embedding API v2 | Embedding API v3 |
|---------|------------------|------------------|
| **Supported dimensions** | 256, 512, 1024 | 384, 768, 1536, 3072 |
| **Default dimensions** | 512 | 1536 |
| **Pricing per token** | $0.00002 per 1,000 tokens | $0.00004 per 1,000 tokens |
| **Max input tokens** | 8,192 | 16,384 |
| **Context window** | 8,192 tokens | 32,768 tokens |
| **Multilingual support** | English only | 50+ languages |
| **Normalization** | L2 normalization optional | L2 normalization by default |

## Supported dimensions comparison

The supported dimensions differ significantly between the two versions. Embedding API v2 supports three dimension sizes: 256 (for high-speed retrieval with small indexes), 512 (the default, balancing speed and accuracy), and 1024 (for higher accuracy in domain-specific applications). Embedding API v3 supports four dimension sizes: 384 (optimized for lightweight edge deployments), 768 (balanced performance), 1536 (the default, matching the Meridian search index default), and 3072 (maximum accuracy for complex semantic matching). The increased dimension count in v3 provides higher fidelity vector representations at the cost of increased storage and compute requirements.

## Pricing per token comparison

The pricing per token differs between the two versions. Embedding API v2 is priced at $0.00002 per 1,000 tokens, making it suitable for cost-sensitive batch processing workloads where absolute accuracy is less critical. Embedding API v3 is priced at $0.00004 per 1,000 tokens, reflecting the improved model quality, larger context window, and multilingual capabilities. At the default dimension of 1536, a document of 10,000 tokens costs $0.40 per 1,000 documents with v3, compared to $0.20 with v2 at the default 512 dimensions.

## Choosing between v2 and v3

Use Embedding API v2 when your use case requires English-only processing, your vectors are stored in a system with strict dimension limits, or your throughput volume makes the lower pricing per token a priority. Use Embedding API v3 when you need multilingual support, require the larger context window of 32,768 tokens, or need the higher accuracy of the 1536 or 3072 dimension sizes. Both versions produce compatible output formats, but vectors generated by different versions should not be mixed in the same index due to dimension mismatch.

## Migration from v2 to v3

Customers migrating from v2 to v3 should re-index their document collections using the new dimensions. Meridian provides a migration script that handles re-embedding with configurable dimension and pricing options. The Embedding API v2 will be deprecated on 30 June 2027.
